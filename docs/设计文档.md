> 配套数据表：`src/data/` 下的 realms / qualities / materials / pills / techniques /
> equipments / enemies / caveBuildings / recipes。本文只描述规则，数值一律以数据表为准。

## 零、计量口径

> 本节定义所有数值讨论使用的计量口径。此前文档里同时存在 290 小时、4 天 1 小时、
> 10 小时、15 小时四个"一世时长"，互相差 6～30 倍却都被当作同一件事讨论。
> **此后凡出现时长数字，必须标注口径代号。**

### 0.1 时长口径

| 代号 | 名称 | 定义 | 当前值 | 产出工具 |
|---|---|---|---|---|
| **P0** | 零加成纯在线 | 无灵根/功法/洞府/buff 加成，连续在线只修炼，不含战斗与奇遇的修为 | **290.7 h / 12.11 天** | `tools/balance_sim.py` |
| **P1a** | 半优化·整局纯在线 | 地灵根×1.8，有余钱即升级（`smoke_session.mjs` 默认 build），连续在线至飞升 | **97 h / 4 天 1 小时** | `tools/smoke_session.mjs` |
| **P1b** | 追满·整局纯在线 | 地灵根×1.8，优先把功法与聚灵阵拉满，连续在线至飞升 | **待测**（粗估 35~45 h） | `smoke_session.mjs --profile=full`（待实现） |
| **P2** | 日历时长 | 真实世界从开新世到飞升的天数 | **6.4 天**（P1a ÷ 0.633） | telemetry `sess` |
| **P3** | 玩家交互时长 | 玩家实际在界面上操作/决策的时长，不含挂机 | **约 2 h/天**（250~300 次点击） | telemetry `act` |

**P1 必须绑定 build 脚本。** "整局时长"是配置随时间爬升的累计量，不是某一个固定配置的
瞬时值——同样的阵容，开局就给和爬到中后期才给，整局时长差很多。所以 P1a / P1b 不是两个
"配置"，是两套 build 顺序。给 P1 数字时必须同时说明用的是哪套 build。

**换算**：`P2 = P1 ÷ 每日有效推进系数`，其中

```
每日有效推进系数 = (每日开屏小时 + 每日关屏小时 × 0.6) ÷ 24
```

0.6 是 `main.js` 的 `OFFLINE_EFFICIENCY`。**改这个常数会动到全部 P2，但 P0 / P1 不变。**

| 每日开屏 | 有效推进系数 | P1a(97 h) 对应 P2 |
|---|---|---|
| 2 h（玩完就关，**当前基准**） | 0.633 | **6.4 天** |
| 4 h | 0.667 | 6.1 天 |
| 8 h | 0.733 | 5.5 天 |
| 全天不关 | 1.000 | 4.0 天 |

**约定**：

- **P0 是理论下界**，任何真实玩家都比它快（战斗、奇遇、丹药都额外给修为）。它不描述体验，
  只作回归基线和模拟器的唯一输出口径。
- **P2 才是玩家体感**。"修炼偏慢"这类反馈一律记账到 P2。
- **P3 是所有玩法目标值（功课门数、劫数次数、塔层数）的锚**——"做 3 次突破"消耗的是
  交互时间，不是挂机时间。`版本规划.md` §7.9 那张表此前是按 P0 耗时占比推的，
  口径错了，需要按 P3 重标。

### 0.2 倍率口径

| 名称 | 定义 | 满配值 |
|---|---|---|
| **原始倍率** raw | `灵根 × (1 + Σ(功法倍率 − 1)) × (1 + 聚灵阵等级 × 0.28)` | **84.7** |
| **有效倍率** sustained | `squashMult(raw, 24)`，实际乘进修速的那个 | 23.99 |
| **隐含倍率** implied | `P0 该境基准时长 ÷ 实际该境耗时` | 逐境浮动，`smoke_session.mjs` 会打印 |

⚠ **功法倍率是槽位求和，不是取最高。** 主修槽位 1/2/3/4 分别对应境界 <6 / <12 / <18 / ≥18
（`state.js` 的 `techSlotsFor`），`techCultBonus += cultMult - 1` 对每个装备中的功法累加：

```
1 槽  最优 [1.46]                      techMult = 1.46
2 槽  最优 [1.74, 1.65]                techMult = 2.39
3 槽  最优 [2.41, 2.32, 2.23]          techMult = 4.96
4 槽  最优 [3.64, 3.38, 3.20, 2.41]    techMult = 9.63
```

README 与 `cultivation.js` 注释中"功法 ≈3.64 / 4.0、原始倍率约 32~35 倍"是**按只装一本
功法**算的，低估 2.6 倍，已作废。

⚠ **软上限在 raw ≈ 30 之后已饱和**：

```
raw= 14.4 → 有效 14.40
raw= 30.0 → 有效 22.11
raw= 60.0 → 有效 23.92
raw= 84.7 → 有效 23.99
```

从 raw 30 拉到 84.7（多投 2.8 倍资源）只换来 **+8.5%**。后期功法投入的边际收益接近零，
与"每一份投入仍有收益"的设计意图不符，列为待修项（见 §0.5）。

**隐含倍率是诊断指标**：它若长期高于有效倍率，说明修为有额外来源（战斗 / 奇遇 / 丹药）。
这正是采集工具 `cult` 事件要拆开的东西。

### 0.3 境界进度口径

| 读法 | 值 |
|---|---|
| **到达筑基**（突破进入 index 9） | 299 分钟 = 5.0 h |
| **筑基境圆满**（突破离开 index 12） | 876 分钟 = 14.6 h |

**统一规定**：写「**到达 X 境**」= 突破进入 X 境；写「**X 境圆满**」= 突破离开 X 境。
`版本规划.md` §7.9 那句"零加成下到筑基累计 14.6 小时"按此应读作 **筑基境圆满**。

## 一、核心循环

```
                 ┌────────────────────────────────────────────┐
                 │                                            │
                 ▼                                            │
   挂机修炼 ──▶ 修为积累 ──▶ 突破（小境界/天劫）──▶ 境界提升      │
      │                          │                    │       │
      │                          │ 失败：跌落/重伤      │       │
      │                          ▼                    ▼       │
      │                     消耗突破丹药        解锁新系统     │
      │                                            │        │
      │              ┌─────────────────────────────┤        │
      │              ▼              ▼              ▼        │
      │          洞府建筑        坊市解锁        探险/战斗塔   │
      │              │              │              │        │
      │              ▼              ▼              ▼        │
      │          灵田产出      购买丹方图纸    击败敌人      │
      │          聚灵加速      买卖灵石        掉落材料      │
      │              │              │              │        │
      │              └──────┬───────┴──────────────┘        │
      │                     ▼                               │
      │              炼丹 / 炼器 ──▶ 丹药+装备 ──▶ 战力提升 ──┘
      │                                            │
      └────────────────────────────────────────────┘
                      战力提升后挑战更高层内容
```

一条线概括：**挂机修炼 → 突破 → 解锁新系统 → 产出材料 → 炼丹炼器 → 战力提升 → 挑战更高内容 → 回到挂机修炼**。
所有系统的产出最终都汇入两个出口：**境界**（决定内容上限）与**战力**（决定能否通过考验）。

## 二、系统规则

### 2.1 修炼

- 主循环 1 tick/秒。每 tick 结算一次修为：
  ```
  calcCultSpeed(state) = baseSpeed(realmIndex)
                       × rootMult
                       × techniqueMult
                       × caveMult
                       × pillBuff
                       × eventBuff
  ```
- `baseSpeed(realmIndex)` 取 `realms.js`，从炼气一层 10/秒 递增到飞升 260/秒（共 26 倍）。
- `rootMult` 取 `spiritRoots.js` 的灵根倍率（杂灵根 0.7 ~ 天灵根 2.5）。
- `techniqueMult = 1 + Σ(已装备功法 cultMult − 1)`，**加法叠加**，避免指数爆炸。
- `caveMult = 1 + 聚灵阵等级 × 0.28`（1 级 +28%，9 级 +252%）。
- `pillBuff / eventBuff` 为限时增益，取当前生效 buff 的累乘，buff 用 `endsAt` 判定过期。
- 修为达到 `REALMS[realmIndex+1].needCult` 时进入"可突破"状态，需玩家手动（或开启自动突破）触发。

### 2.2 突破与天劫

> 实现见 `src/systems/breakthrough.js`。本节描述**代码实际行为**。

**判定是否天劫**：当前境界索引命中 `TRIBULATION_REALMS = {9,12,15,18,21,22,23,24}` 时，
突破该境界为大境界关口，触发三轮天劫；否则走普通突破判定。

**前置条件（两种突破共通）**：
1. 修为达到当前境界 `needCult`（修为会在 `needCult` 处封顶，不会溢出浪费）
2. 若该境界 `needPill` 非空，**必须持有对应丹药**——丹药是硬门槛，不是加分项

**普通突破**：
```
calcBreakChance = clamp(
    REALMS[当前].breakChance            // 炼气期为 1.0，筑基/金丹/元婴/化神小境界为 0.94
  + 突破丹 bonus                        // +0.05 ~ +0.08
  + clamp((悟性 − 10) × 0.004, 0, .15)
  + clamp((道心 − 10) × 0.005, 0, .15)
  + clamp((气运 − 50) × 0.0008, −.04, .04)
  + min(连败次数 × 0.08, 0.40)          // 保底
  + 静心丹等临时加成,
  0.05, 1.0 )
```
- **`breakChance = 1.0` 的境界直接短路返回 100%**，不叠加任何修正（炼气期不允许失败）。
- 上限是 **1.0 而非 0.95**：投入足够的玩家应当能真正做到稳过。
- **失败**：损失 `needCult × 25%` 的修为，连败计数 +1（下次成功率 +8%，上限 +40%）。
  **不清零、不跌落境界**——这是配平报告的核心要求，避免后期退化成"反复赌概率"。

**大境界天劫**：固定顺序 **雷劫 → 火劫 → 心魔劫**，三轮各判定一次。
任一**轮**失败只是受创；只有**气血被打空**才判天劫失败，所以血厚本身就是一种抗劫能力。

抗劫值按轮加权——三劫考的不是同一道题：
```
resilience(劫) = 道心×w.dao + ⌊防御/10⌋×w.def + ⌊气血上限/200⌋×w.hp + 护山大阵等级×5 + 丹药护持

       w.dao  w.def  w.hp   考校
雷劫    0.5    1.0    0.5   护体（外劫，看护体与法宝）
火劫    0.6    0.4    1.0   气血（内劫，看气血底蕴）
心魔劫  1.5    0.2    0.4   道心（心劫，只看道心）

天劫威压  difficulty = 10 + (realmIndex − 9) × 7
单轮通过率 = clamp( 0.5 + (resilience(劫) − difficulty) × 0.015, 0.15, 0.95 )
```
设计意图：堆防御过得了雷劫却未必扛得住心魔劫，逼玩家全面发展；
开劫时会在日志与弹窗里点名"你最薄弱的是哪一劫、它考校什么"。

**天劫失败后果**（不跌落境界——对休闲向游戏太残酷）：
| 项 | 后果 |
|---|---|
| 气血 | 降至上限的 20% |
| 修为 | 损失当前修为的 30% |
| 道心 | 永久 −2 |
| 虚弱 | 「重伤」buff 持续 600 秒，修炼速率 ×0.7 |
| 保底 | 连败计数 +1，下次成功率 +8%（上限 +40%） |

**自动突破**：`meta.autoBreakthrough` 开启后，每 tick 检查一次；
修为满、丹药齐、成功率 ≥ `meta.autoBreakThreshold`（默认 0.55）时自动破关。
**天劫关口永不自动闯**——那是情绪峰值，必须由玩家亲手点。

### 2.3 战斗

回合制，双方轮流出招。派生属性均由 `systems/cultivation.js` 汇总（裸属性 + 装备 + 功法 + 洞府）。

**出手序**：按 `calcSpd` 降序；同速时玩家先手。每回合每个单位行动一次；多单位战斗按速度序列逐个结算。

**灵力消耗**：
- 玩家：普通攻击消耗 0、倍率 1.0；灵力足够时放**灵力技**，倍率 1.6，
  消耗 `max(8, ⌊maxMp × 0.2⌋)`。灵力不足只能普攻。
- 敌人：**不消耗灵力、也没有冷却**，从自己的 `skills` 里等权随机抽一个招式。

**单次攻击结算顺序**（严格按此顺序，避免歧义）：
```
1. 闪避判定    dodge = clamp(0.03 + (守方spd − 攻方spd) × 0.004, 0.02, 0.25)
               闪避成功 → 本次无伤害，不触发后续任何效果
2. 伤害        base = max(1, atk × 技能倍率 × mp_power 词条加成 − def × 0.6)
3. 暴击        rng < crit → base ×= critDmg
4. 伤害波动    base ×= rand(0.92, 1.08)
5. 反伤        守方按所受伤害 × reflect 回敬攻方（无视防御，不可暴击/闪避）
6. 吸血        攻方回复 实际伤害 × lifesteal
7. 溅射        aoe 倍率 × 实际伤害，作用于同一目标的余波（单挑没有第二目标）
8. 追加一击    玩家行动后 rng < extra_strike → 追加一次 0.7 倍率攻击，每回合至多一次
9. 灵力回复    玩家每回合恢复 mp_regen 词条值的灵力
```
- 治疗类技能：回复 `calcMaxHp × 技能倍率`（敌人用其 `base.hp`）。
- 减益（debuff）：最多叠 3 层，总削弱**上限 50%**，以开战时的数值为基数。
- 胜负：任一方气血 ≤ 0 结束；**50 回合**仍未分胜负判**玩家败**（杜绝死循环）。
- 玩家出招（战斗中固定生效，无手动操作）：灵力够就放灵力技，否则普攻。
- 玩家气血低于 20% 且身上有回血类丹药时，**自动服用一次**（每场限一次）。
- 战斗没有"手动/自动"之分：玩家的决策只有**迎战 / 避战**（奇遇选项文字、是否点探险）。一旦开打，结算统一由 `autoResolve` 完成。
- `meta.battleReport` 只控制**战报展示**：开启时弹窗逐条播放，关闭时只在日志留一行胜负与战利。**不影响任何结算**。
- 各入口的战报展示策略：**奇遇**受 `meta.battleReport` 控制（弹窗 / 日志摘要二选一）；**探险**恒为日志摘要（30 秒一次的高频操作，逐条流水会冲掉整个日志面板）；**试炼塔**恒为专属弹窗 + 一行破层里程碑日志。
- 实现上，凡是"逐条战报另有展示渠道"的入口，调 `autoResolve` 一律带 `silent: true`，再用 `battleSpoils()` 补一行战利摘要。`silent` 只挡日志输出，不影响结算。
- 战斗结束：胜利按 `loot` 逐条掷骰掉落材料与灵石，另加一笔**修为**（= 15 秒的当前挂机产出）；
  失败**不倒毙**——气血回写到 `max(1, 剩余)`、灵力 `max(0, 剩余)`，由修炼系统慢慢恢复，
  `stats.deaths++`。**没有灵石损失，也没有虚弱 debuff**。
- ⚠ 护山大阵的减伤**只作用于天劫抗劫值**（见 2.2），不影响普通战斗。建筑数据里的 `defense` 效果
  目前只在 `breakthrough.js` 被读取。
- **试炼塔奖励是另一套口径**：`challengeTower` 传 `noCult: true`，不领上面那 15 秒的常规战斗修为；
  改为在**首次破层**时一次性发放塔层奖励——修为 + 灵石，额度随层数线性递增，每满 10 层再追加一档。
  详见下方的 **2.9 试炼塔**。

### 2.4 炼丹

- 消耗对应**丹方** + 材料 + 时间，产出 `pills.js` 中的丹药，`stats.pillsMade++`。
- 实际耗时 `= max(1, ⌊recipe.seconds / (1 + 丹房等级 × 0.12)⌋)`。
- 实际成功率 `= clamp(recipe.baseSuccess + 丹房等级×0.02 + 悟性×0.004, 0.05, 0.98)`。
- 失败返还 50% 材料，不产丹。
- 丹房达到 **3 级**解锁**自动炼丹**（`alchemy.auto`）：队列为空时自动选择材料充足、品阶最高的丹方循环起火。
- **丹方只能在坊市参悟**（「丹方图纸」栏，费用 `unlockCost`），习得后写入 `alchemy.knownRecipes`，永久有效。
  炼丹界面**只列出已悟的丹方**、只显示丹药名；未悟的根本不出现，面板里也不再提供参悟入口——
  同一件事有两个入口，价格与解锁条件就容易各说各话。
- **修为丹**（聚气丹 / 蕴灵丹 / 紫府丹 / 造化丹 / 大衍丹）**不在坊市货架上**，
  理由是静态价格绕不开的结构性错配：灵石收入从炼气到渡劫涨约 18000 倍，修为速度只涨 25 倍。
  它们的来源是奇遇掉落、宗门宝库兑换，或自己买丹方来炼。

### 2.5 炼器

- 消耗**图纸** + 材料 + 时间，产出 `equipments.js` 中的装备。
- 实际耗时 `= max(1, ⌊recipe.seconds / (1 + 炼器室等级 × 0.12)⌋)`。
- 实际成功率同炼丹公式；成功后掷**升品**：`minQuality` 为保底，
  另有 `clamp(0.10 + 悟性×0.002 + 炼器室等级×0.015, 0, 0.60)` 概率提升一阶，
  每再升一阶概率 ×0.4（最高圣品）。
- 成品写入 `equipment.owned`，带 `quality / level=1 / affixes`（词条数量见 `qualities.js` 的 `affixCount`）。
- 炼器室达到 **3 级**解锁**自动炼器**。
- **器图只能在坊市参悟**，炼器界面同样只列已悟的器图、只显示装备名。

### 2.5.1 丹药与装备的定价锚

两者的坊市价都不是手写的，而是从**材料成本**推出来的。成品价锚定材料、材料价锚定收入曲线：

```
丹药价 = Σ(材料买入价 × 数量) ÷ 基础成功率 × 1.4 ，再钳进 [材料×1.2, 材料×2.5]
装备价 = 同上公式（可锻造的那一件）
       └ 同境界组（minRealm 相同）的另外两件装备按同一比例跟随，保持组内相对关系
参悟费 = 对应成品的坊市价（参悟一次 ≈ 买一件成品）
```

- **下界 ×1.2** 保证不会出现「买成品比买原料还便宜」的倒挂。
- **上界 ×2.5** 是防刷灵石线的余量版：材料卖出价 = 原价 × `SELL_RATE(0.35)`，
  所以成品价一旦超过材料买入价的 `1/0.35 ≈ 2.857` 倍，满成功率下「买材料 → 制作 → 卖出」即可套利。
  成功率会被建筑等级与悟性抬到 0.98，**这条线必须按满成功率卡**，不能按基础值。
- 改丹方材料、装备材料或基础成功率时，必须同步重算这三处的价格。
  `tools/test_economy.mjs` 的「炼制/锻造产物出售价 < 材料买入成本」会挡住越界。

### 2.6 洞府

- 洞府等级 `cave.level ∈ [1, 9]`，由玩家消耗灵石升级，限制各建筑的 `reqCaveLevel`。
- 六座建筑（见 `caveBuildings.js`）：

| 建筑 | art | 效果 | 解锁 | 洞府等级 |
|---|---|---|---|---|
| 聚灵阵 | `BLD_SPIRIT_GATHER` | 修炼速率 +28%/级 | 炼气 | 0 |
| 灵田 | `BLD_HERB_FIELD` | 每 600 秒产 `等级 × 1` 份灵材 | 炼气 | 1 |
| 丹房 | `BLD_ALCHEMY_ROOM` | 炼丹加速 12%/级；**3 级**解锁自动炼丹 | 炼气四层(idx3) | 2 |
| 炼器室 | `BLD_FORGE_ROOM` | 炼器加速 12%/级；**3 级**解锁自动炼器 | 炼气七层(idx6) | 3 |
| 藏经阁 | `BLD_LIBRARY` | 悟性 +20/级（见下方 ⚠） | 筑基初期(idx9) | 4 |
| 护山大阵 | `BLD_WARD` | 天劫抗劫值 +5/级（**只作用于天劫**，不减普通战斗伤害） | 金丹初期(idx12) | 6 |

- 升级费用 `= floor(cost.base × cost.growth^当前等级)`，耗时 `= floor(buildSeconds.base × buildSeconds.growth^当前等级)`，**离线照常推进**。

> ⚠ **两处数据与代码不一致，尚未裁决**（记录的均为代码实际行为）：
> 1. `caveBuildings.js` 里丹房 / 炼器室的 `autoUnlockLevel` 写的是 **5**，建筑 `desc` 也向玩家显示“五级后解锁”，
>    但 `alchemy.js` / `forging.js` 的 `AUTO_*_MIN_LEVEL` 是 **3**（`alchemy.js` 的注释自陈“任务约定 3，
>    data 里为 5”）。玩家在洞府面板看到的是 5，实际 3 级就能开——提示与行为对不上。
> 2. 藏经阁数据写 `perLevel: 2`，但 `calcComprehension()` 里是 `caveEffect('bld_library') * 10`，
>    即实际 **+20/级**。两者差 10 倍，不确定哪边是笔误。

### 2.7 坊市

- **买**：装备 / 丹药 / 材料按数据表 `price`（丹药与装备还会乘立场物价倍率）；丹方与图纸按 `unlockCost`。
- **卖**：一律 `floor(估值 × SELL_RATE)`，`SELL_RATE = 0.35`（装备的估值见 `inventory.js` 的 `equipmentValue`）。
  买卖必亏是硬约束——`SELL_RATE < 1`、材料买入另乘 `BUY_MARKUP = 2`，任何「买入 → 卖出」的循环都亏。
- **上架规则按品类不同**：
  | 品类 | 过滤条件 |
  |---|---|
  | 丹药 | `minRealm <= 当前境界` 且**非** `noShop`（五档修为丹不上架） |
  | 装备 | `minRealm <= 当前境界` 且 `tier <= realmTier(当前境界) + 1` |
  | 材料 | **不过滤**，16 种全在架上（低境界也能买高阶药材，只是买不起） |
  | 丹方 / 图纸 | `minRealm <= 当前境界` |
- 灵石三品自动进位 / 拆分（`normalizeStones`），付费优先花低品阶。
- **拍卖行**：每 6 小时轮换一批，3 个槽位（丹药 / 装备 / 灵材各一），
  价格 = 常规买入价 × （1.20 ~ 1.69），库存 1，买走记入 `flags` 本轮不再刷出。
  轮换按时间确定性散列选货，不消耗全局随机序列。

### 2.8 探险

- 手动触发的单次派遣，**冷却 30 秒**（`EXPLORE_CD`），消耗 **12% 气血上限**。
  冷却与派遣都**不持久化、不离线推进**——探险是"人在电脑前"的主动玩法。
- 结果池三档，按序判定：

  | 权重 | 分支 | 内容 |
  |---|---|---|
  | 40% | 战斗 | 从 `enemiesByRealm(realmIndex)`（最近三档）随机取一只，走 `autoResolve({ silent: true })`；战报只留一行胜负摘要，避免 30 秒一次的逐条流水冲掉日志 |
  | 35% | 拾取 | `realmTier()` 档灵材 ×1~3，另加灵石 `randInt(40,120) × incomeScale()` |
  | 25% | 高阶奇遇 | `rollEncounter({ tiers: ['good','rare'], preferTier: 'rare' })`；池空时退化为一份灵材 |

- 战斗胜利后有 12% 概率遭遇可收服灵兽（收服本身再有 45% 成功率）。
- 探险**不产出丹方 / 图纸**——两者只能从坊市参悟。

### 2.9 试炼塔

- 敌人池取 `enemiesByRealm(当前境界)`（最近三档，按 `power` 升序），按层数在池内轮转：
  第 `f` 层的缩放为**气血 ×(1 + 0.22×(f−1))、攻击 ×(1 + 0.14×(f−1))**。
- 面板提供「挑战第 N 层」，N 恒为 `towerFloor + 1`；胜则层数 +1，败则退走（战败不倒毙）。
- 胜率预测由 `simulateBattle` 采样 20 次估算，与实际战斗同口径（含出战灵兽），走固定种子所以数字不闪。
- **奖励只在首次破层时发放**（`info.floor > prev` 才发），额度随层数线性递增：

  ```
  修为 = calcCultSpeed() × (60 + 6×floor + 60×⌊floor/10⌋) 息
  灵石 = incomePerMin() × (2 + 0.4×floor + 2×⌊floor/10⌋) 分钟的产出
  ```

  锚定**速率/收入**而非 `needCult` 百分比，与战斗、奇遇奖励同口径；锚百分比会让塔的贡献随境界时长一起膨胀。
  另外塔层仍会带出守关敌人的普通掉落（与野外打同一只敌人一致）。
- 已破的层**不可重刷**：塔是攀爬目标，不是资源点。若能重刷，它就会变成挂机的替代品。
- 塔层进度写入 `state.combat.towerFloor / towerBest`，**随存档持久化**。

## 三、洞府离线产出规则

- `meta.lastTick` 记录上次结算时间戳；读档时：
  ```
  elapsed = clamp(now − lastTick, 0, offlineCapHours × 3600)   // 默认 8 小时
  ```
- 离线收益（按离线开始时的 `calcCultSpeed` 快照结算，过期 buff 不生效）：
  1. **修为**：`cult += calcCultSpeed × elapsed`，超过 `needCult` 部分保留，不自动突破（除非开启自动突破）。
  2. **灵田**：`收获次数 = floor(elapsed / 600)`，每份产出 `灵田等级 × 1` 个当前境界段灵材（tier 由 `realmIndex` 决定，随机取该 tier 白名单之一）。
  3. **建筑**：`upgradeEndsAt` 为绝对时间戳，离线期间照常倒计时，到点即完成。
  4. **自动炼丹 / 炼器**：进行中的任务按 `endsAt` 结算；若已完成且开启自动，则连续补炼，受材料上限约束（最多结算到材料耗尽）。
- **不产出**：离线不进行战斗与探险（除已派遣的探险按次结算），不产出坊市灵石收入。
- 超出 `offlineCapHours` 的时间直接丢弃，不折算。上限可通过特殊道具 / 奇遇提升。
- 结算完毕写回 `meta.lastTick = now`，并把主要收益汇总成一条 `channel:'system'` 的日志。

## 四、玩家成长路径节奏表

战力门槛取 `enemies.js` 中该段敌人的 `power` 区间；时长为含灵根、聚灵阵、功法加成的**设计目标挂机时长**（非裸倍率）。

| 境界段 | 索引 | 解锁重点 | 敌战力区间 | 目标装备 tier | 目标时长 |
|---|---|---|---|---|---|
| 炼气期 | 0–8 | 修炼、洞府、灵田、丹房、炼器室 | 35 – 63 | t1（140~630 灵石） | 30–60 分钟 |
| 筑基期 | 9–11 | 天劫①、藏经阁、金丹丹方 | 210 – 305 | t2（1700~3700） | 2–4 小时 |
| 金丹期 | 12–14 | 天劫②、护山大阵、法宝槽成型 | 1560 – 2450 | t3（7300~2.2万） | 6–12 小时 |
| 元婴期 | 15–17 | 天劫③、高阶图纸、自动炼丹普及 | 8100 – 14300 | t4（3.7万~10万） | 1–2 天 |
| 化神期 | 18–20 | 天劫④、圣品材料登场 | ≈ 56200 | t5 下段 | 2–4 天 |
| 炼虚期 | 21 | 天劫⑤、混沌石 | ≈ 72400 | t5 | 3–5 天 |
| 合体期 | 22 | 天劫⑥ | ≈ 83200 | t5 | 4–7 天 |
| 大乘期 | 23 | 天劫⑦ | ≈ 107200 | t5 上段 | 7–12 天 |
| 渡劫期 | 24 | 天劫⑧（最强天劫） | ≈ 128900 | t5 顶 | 10–20 天 |
| 飞升成仙 | 25 | 终局内容、成就结算 | — | — | 终局 |

**节奏设计意图**：
- 每次大境界突破（天劫）都是一次「装备 + 丹药 + 道心」的综合考试，逼迫玩家在三条成长线上都不掉队。
- 装备价格由 `equipments.js` 的材料成本锚推出（见 **2.5.1 丹药与装备的定价锚**）。
  折合该段境界的收入约 **3~140 分钟**：同一 tier 内装备与收入基线同时抬升，
  但收入涨得更快（渡劫期收入是化神初期的 72 倍），所以越到后期装备越"便宜"。
  它的作用是保证「打不过 → 攒钱换装 → 打得过」的正反馈，而不是充当灵石的主要去处——
  灵石的主去处是洞府建筑、功法与丹药。
- 天劫间隔逐级拉长，但每级解锁的新系统（自动炼丹 / 自动炼器 / 藏经阁 / 护山大阵）都在放大挂机效率，形成「长挂机 + 高回报」的循环。
